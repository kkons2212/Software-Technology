### Basic Course of Events

| Actor Action | System Response |
| :--- | :--- |
| **1.** Admin / Museum Staff accesses the admin portal and submits login credentials. **[A1]** | |
| | **2.** System validates credential format and sends verification request to the Authentication Service. **[E1]** |
| | **3.** Authentication Service verifies credentials against stored records and confirms account status. **[E2] [E3]** |
| | **4.** System establishes an authorized session and grants access to the Admin Dashboard according to role permissions. |

---

### Alternative Paths

#### **A1. Active Session Exists (Auto-Login)**
| Actor Action | System Response |
| :--- | :--- |
| **1.** Actor accesses the administrative portal with an active unexpired session. | |
| | **2.** System verifies session validity and bypasses credential entry. |
| | **3.** Proceed directly to Step 4 of the Basic Course of Events. |

#### **A2. User Logout**
| Actor Action | System Response |
| :--- | :--- |
| **1.** Authenticated Actor requests to log out. | |
| | **2.** System terminates the active session, invalidates session tokens, and returns to unauthenticated state. |

---

### Exception Paths

- **E1:** At step 2, if credentials are empty or malformed, the system displays an input error message and returns to Step 1.
- **E2:** At step 3, if credentials are incorrect or the user is not found, the system displays a generic error message, records the failed attempt in the audit log, and returns to Step 1.
- **E3:** At step 3, if consecutive failed attempts exceed the allowed threshold (5 times) or the account is inactive, the system temporarily locks the account, logs a security alert, and terminates the use case.
- **E4:** At step 2 or 3, if the Authentication Service or database is unreachable, the system displays a service outage notification and terminates the use case.

### Business Rules Mapping

1. **BR-AUTH-01 (Password Encryption & Storage):** Passwords must be hashed using industry-standard one-way cryptographic algorithms (Bcrypt with cost factor ≥ 12 or Argon2id). Plaintext passwords must never be stored, cached, or logged.
2. **BR-AUTH-02 (Anti-Brute-Force & Lockout Controls):** Generic error messages must be returned on failed logins to prevent user enumeration. Accounts are temporarily locked for 15 minutes after 5 consecutive failed attempts.
3. **BR-AUTH-03 (Session Lifetime):** Access tokens have a maximum lifespan of 60 minutes and must be transmitted via secure, `HttpOnly`, `SameSite=Strict` cookies.
4. **BR-AUTH-04 (Role-Based Access Control - RBAC):**
   - `ADMIN`: Full administrative control (User management, POI CRUD, system configuration, audit logs).
   - `CURATOR`: Exhibit content management, translation review, audio regeneration.
   - `STAFF`: Exhibit viewing, media upload, and QR code printing.
