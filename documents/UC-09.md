# Use Case Specification: UC-09

---

| Field | Content |
| :--- | :--- |
| **Use Case Number:** | **UC-09** |
| **Use Case Name:** | Visitor Payment & Visiting Session Activation |
| **Actor(s):** | Visitor (Primary), Third-Party Payment Gateway (Secondary / External), Core System (Secondary) |
| **Maturity:** | Focused |
| **Summary:** | Visitor pays for the museum tour pass (single fixed price) by choosing between Domestic VietQR or International Card. Once payment is confirmed by the Payment Gateway via Webhook, the system automatically activates a Visiting Session to unlock full POI details and audio guides. |
| **Reference: Business Rules:** | |

---

### Basic Course of Events

| Actor Action | System Response |
| :--- | :--- |
| **1.** Visitor clicks "Unlock Audio Guide Service" from the home screen or locked exhibit. | |
| | **2.** System displays the fixed Audio Guide service fee and payment options (VietQR or Credit/Debit Card). |
| **3.** Visitor selects a payment method. **[A1]** | |
| | **4.** System calls the **Payment Gateway (PayOS / Stripe)** to generate a payment request. **[E1]** |
| | **5.** System displays the payment interface (VietQR code or Card input form). |
| **6.** Visitor completes the payment. | |
| | **7.** Payment Gateway confirms successful transaction and sends a Webhook notification to the System. **[E2]** |
| | **8.** System verifies the Webhook, creates an active **Visiting Session** (valid for 24 hours), unlocks all exhibits/audio guides, and redirects the Visitor to the tour view. |

---

### Alternative Paths

#### **A1. Visitor Resumes an Existing Session (Restore Access)**
| Actor Action | System Response |
| :--- | :--- |
| **1.** Visitor clicks "Restore Tour Session" and enters their previous Session Code. | |
| | **2.** System verifies that the session is still active and valid. **[E3]** |
| | **3.** System restores access immediately without requiring another payment. Proceed to Step 8 of the Basic Course of Events. |

---

### Exception Paths

* **E1:** At step 4, if the Payment Gateway is unreachable, the system displays an error message, allows the visitor to retry, and returns to Step 2.
* **E2:** At step 7, if the payment fails (insufficient funds, cancelled, or expired), the system displays a failure notification and returns to Step 2 to initiate a new payment.
* **E3:** In path A1 (at step 2), if the session code does not exist or has expired, the system displays an invalid session notice and redirects the visitor to Step 2 of the Basic Course of Events.

---

### Supplementary Information

| Field | Content |
| :--- | :--- |
| **Triggers:** | Visitor clicks "Unlock Tour" on the app or tries to access locked audio guide content. |
| **Assumptions:** | Museum charges a single fixed admission/audio guide fee per session; visitor's device saves the session token in `localStorage`. |
| **Preconditions:** | Visitor has network connection and accesses the web application. |
| **Postconditions:** | Transaction record is saved with status `PAID`; a `VisitingSession` is activated with an expiration timestamp. |
