## Overview

* **Summary:** The Admin / Museum Staff monitors real-time and historical visitor traffic across the outdoor heritage site (GPS proximity triggers, open-air heatmaps, multilingual audio guide consumption, dwell times) and assesses infrastructure system health (telemetry ingestion latency, audio cache storage, database query performance, and external AI services).
* **Triggers:** Admin / Museum Staff logs into the Admin Portal and accesses the "Traffic & System Health" dashboard.
* **Preconditions:**
  1. Actor has authenticated with administrative privileges.
  2. The Analytics & Logging Module is active and receiving telemetry events (GPS proximity detections, audio streaming requests) from visitor mobile PWAs.
* **Postconditions:**
  1. Aggregated outdoor traffic metrics, visitor density heatmaps, and system health status indicators are rendered.
  2. Any operational anomalies (e.g., storage capacity thresholds, degraded AI services) are logged into the system audit trail.

### 3. Exception Paths

* **E1: Analytics Aggregation Timeout / Query Delay:**
  * At Step 3, if processing a massive volume of GPS telemetry logs times out or database write locks cause a delay:
    1. System falls back to rendering cached metrics from the previous snapshot.
    2. System displays a notification banner: *"Real-time telemetry delayed. Displaying cached data from [Timestamp]. Auto-retrying..."*
    3. System attempts to re-query in the background after 30 seconds.
    4. System proceeds to Step 4 of the Main Event with cached data displayed (Use case continues).
* **E2: Storage Capacity Threshold Exceeded:**
  * At Step 6, if the static audio cache directory (`/static/audio`) or server disk usage exceeds 85% capacity:
    1. System flags the storage health indicator with a warning status (`WARNING / CRITICAL`).
    2. System triggers an alert on the Admin Dashboard prompting staff to prune orphaned audio files or expand storage quota.
    3. System keeps all dashboard views active and proceeds to Step 7 of the Main Event (Use case does not terminate).
* **E3: External AI Pipeline Degradation:**
  * At Step 6, if the Edge-TTS engine or Translation API experiences connection dropouts, high latency, or rate limiting:
    1. System marks the corresponding service badge as `DEGRADED` or `OFFLINE`.
    2. System logs the error event into the Audit Log and notifies Admin that background audio generation for new POIs may be temporarily queued.
    3. System keeps all dashboard views active and proceeds to Step 7 of the Main Event (Use case does not terminate).
